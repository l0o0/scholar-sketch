# Markdown 持久化索引

Scholar Sketch 使用 Zotero 的 `DBConnection`，在 Zotero 数据目录中创建
`scholar-canvas-index.sqlite`。这是插件自己的可重建缓存，不修改 Zotero 核心表，
也不通过 Zotero 附件同步上传。Markdown 附件仍是原始数据。

## 保存的数据

- `notes`：以 `(libraryID, noteKey)` 为主键，保存文件名、标题、群组 ID、
  文件路径、修改时间、大小和 Markdown 正文。
- `links`：保存来源笔记、链接地址、显示文字、语法类型和原文起止位置。
  同一笔记内重复出现的链接分别保留。
- `PRAGMA user_version`：当前模式版本为 1。今后修改表结构或解析规则时需更新版本
  并实现迁移或重建；较新版本的数据库会被保留，旧插件回退读取 Markdown。

目标笔记仍基于当前文库元数据解析，避免重命名或新增同名文件后复用过期的匹配结果。
目前没有实现全文搜索或 FTS 表。正文已经独立存储，后续可以增加 FTS 索引和查询接口。

## 更新与一致性

首次访问一个文库时枚举现有 Markdown 附件，并加载 SQLite 缓存。路径、修改时间和
大小一致的文件复用正文及解析结果；变化的文件重新读取，读取前后文件状态一致才记下
可复用的状态。手工保留修改时间且保持大小的编辑需要使用强制刷新。

保存 Markdown 后，即使没有打开反向链接面板，也会排队更新数据库。保存路径不依赖
索引成功；数据库异常只记录日志并在本次运行中停用缓存，原文件照常保存。

所有数据库操作排队执行。文库扫描的写入使用事务，并在事务中检查扫描是否已被新保存
或缓存失效事件取代；过期扫描会回滚。完整扫描会清理该文库内已删除、已移入回收站或
无法读取的笔记缓存。未发生变化的记录不重复写入。

Zotero 条目/文件通知及切回应用会使内存缓存失效，下次扫描校验文件状态。
打开的反向链接面板会触发扫描。插件关闭时等待已排队操作完成并关闭连接。

## 重建

反向链接面板的“刷新”按钮强制从当前文库的 Markdown 文件重新读取并解析，
不受缓存文件状态匹配影响。程序入口为 `rebuildNoteLibrary(libraryID)`。

数据库无法打开或损坏时，可退出 Zotero 后移走插件的
`scholar-canvas-index.sqlite` 及同名前缀的 SQLite 日志文件，再启动重建。
不要移除 Zotero 自身的 `zotero.sqlite`。数据库缓存无需作为笔记备份；备份应包含
原始 Markdown 及其资源附件。

## 验证

`test/document-links-index.test.ts` 使用 Node 的真实 SQLite 引擎运行生产 SQL，覆盖
重新打开数据库、重复链接、文库隔离、删除清理、事务回滚、保存并发、文件状态校验、
强制重建和索引错误回退。Zotero 的连接包装器仍需在宿主环境中验证。
